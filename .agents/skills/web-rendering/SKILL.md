# Rendering rules — prerendered (SSG) websites

For marketing/content sites that must be found by search engines **and AI/LLM crawlers**. Stack-agnostic principles; the reference implementations were Vite + Vue 3 + vite-ssg + @unhead/vue (two projects — a multi-page law-firm site and a bilingual one-page personal-brand site), but only file names change elsewhere.

## Prime directive

- A client-only SPA ships a near-empty shell (~800 bytes, home title on every URL). Prerender every route to real HTML at build time, from day one — retrofitting means auditing every place JS injects content. The argument doesn't rest on Google failing: Google/Gemini *can* render JS, but it costs a render-queue delay, fails edge cases, and spends crawl budget. **Every other AI crawler (GPTBot, ClaudeBot, PerplexityBot, CCBot, Bingbot at scale) fetches HTML and does not execute JS at all** — measured, not assumed. Client-rendered content is invisible to the systems that write AI answers.
- Everything a crawler needs must be in the response **with JS disabled**: headings, body copy, internal links as real `<a href>`, per-page title + description, absolute self-canonical, reciprocal hreflang, JSON-LD.
- Standing rule: **content lives in the template; JavaScript is for non-essential interactivity only.** Interactive non-content widgets (captcha, maps, embeds) are the exception and load client-side in mount.
- Content links stay plain `<a href="/path">` in the markup; a single global click interceptor upgrades same-origin clicks to SPA navigation (skipping modified clicks, `target`, mailto/tel/external). Crawlers walk real links; users get SPA navigation; new internal links need no wiring.
- Progressive disclosure ships EXPANDED: the static HTML carries the full list; the collapsed/preview state is gated on a client "hydrated" flag set on mount. Crawlers and JS-off readers get everything; the collapse is purely an affordance.

## Isomorphic constraints

- Nothing touches `document`/`window` at module scope or in setup — that code runs in Node during prerender. All DOM work in `onMounted`, torn down in `onUnmounted`.
- One app factory used by both build and browser; export a routes array, never instantiate a router singleton at module scope (the SSG tool owns history creation — memory history at build, web history in the browser). (confirmed in 2nd project)
- Enumerate prerender routes from the **server entry**, not the bundler config — the server entry gets env substitution, so it can read CMS creds and enumerate dynamic slugs with no plumbing.
- SSR→client handoff: fetch in the server-prefetch hook, stash on route meta, client seeds from it and re-fetches only when absent.
- The locale ref flips in the router's `beforeResolve`, NOT `beforeEach`: views are lazy, a navigation is async, and flipping at the start leaves the OUTGOING view mounted and reactive — it repaints in the new language, in full, for as long as the route takes to commit (~140ms measured) before the swap blanks it. `beforeResolve` lands the flip and the view swap in one update.
- Any effect that captured live DOM text (typewriter, language sweep) must cancel and RESTORE its captured strings BEFORE the reactive source flips — while the restored text still matches the on-screen language — so the framework's re-render patches over clean text, not half-typed fragments.

## The traps that pass a green build

1. **Copy that originates in JS prerenders blank.** Text typed in from `data-*` attributes, `createElement`'d links, images whose real `src` is set by JS, elements hidden by inline JS and "revealed" later — all invisible to crawlers. Effects READ what the template declares and animate it; they are never the source of it.
2. **Hidden states live in JS, never CSS.** Not for cloaking reasons — Google indexes CSS-hidden content, and no-JS crawlers parse the text whatever the CSS says. The real reasons: (a) with JS off, a CSS-hidden state has no reveal path, so human readers and the litmus test see nothing; (b) JS-applied hiding can skip elements already on screen (no blink-out) and guarantees a bounded way back (disconnect the observer FIRST, then force-show). The static HTML always carries the complete, visible page.
3. **Shared mutable module state races under parallel prerender.** A module-level locale/theme ref set per-page by a router hook + default render concurrency = every page comes out in the last locale that won. Render serially (`concurrency: 1`) or isolate context per render, and guard it with a build assertion. (confirmed in 2nd project)
4. **A throw during any route's render fails the whole build.** Missing record → emit `noindex` head + graceful empty state, never throw. Wrap build-time CMS enumeration so an outage ships the static pages instead of failing the deploy.
5. **A generated config can shadow the real one.** `vue-tsc -b` with `composite: true` emits `vite.config.js` which shadows `vite.config.ts` (resolves first) and silently drops your ssgOptions. `emitDeclarationOnly: true` in the node tsconfig; if the `.js` reappears, delete it and re-check.
6. **Never bake mock/sample fallback data into SSR output.** Prerender the empty shell and let the client refill; placeholder content in permanent static HTML is worse than nothing.
7. **Per-view runtime theming = brief FOUC on hard load** (tokens applied on mount). Acceptable; content/metadata correct. Inline critical tokens into `<head>` if it matters. When per-view tokens have no cleanup by design (next view's mount overwrites), every view must assert its COMPLETE token set — a var only one page sets leaks to the next.
8. **The CSS minifier can merge duplicate selectors and DROP declarations** — a production-only loss (dev CSS is unminified). It once silently removed `touch-action` from a fullscreen overlay = dead pan on iOS only. Keep load-bearing declarations in ONE rule block per selector, grep the BUILT css for them after changes near them, and mirror the truly critical ones as inline styles set from JS — an inline style survives any build transform.
9. **A wrapping flex row breaks lines using each item's flex-BASIS, before any shrinking.** So "fits on a 390px iPhone, wraps on a 360px Android" is a bug class, not a platform bug — the layout depended on a few spare pixels. Atomic groups (a number and its icon) go in a nested NON-wrapping row so they can never be orphaned; phone layouts get a deterministic basis (`flex-basis: 100%` under the breakpoint) instead of pixel arithmetic. And an inline `flex` shorthand outranks any stylesheet rule — layout you will ever override belongs in the (scoped) stylesheet, never the style attribute.
10. **Global `scroll-behavior: smooth` turns every programmatic scroll into an animation.** Per-frame corrective loops then chase a target that moves again next frame and never settle; route-change resets glide when they should snap. Every corrective/reset scroll passes `behavior: 'instant'` explicitly (confirmed twice in one project: router scroll reset, collapse anchor-hold).

## Head, i18n, structured data

- One `useHead`-style call per view, driven by content data, reactive to locale. Canonical always absolute (origin from ONE constant — `window.location` is undefined at build). Missing data still emits valid canonical + hreflang + non-empty title **plus `noindex`** so guards pass and the page stays out of the index.
- **Single-locale pages in a multilingual site need their own head variant**: self-referential canonical, self-referential `<locale>` + `x-default` hreflang, and **no alternate for the missing locale** — advertising an alternate that hard-404s is a real error, and the sitemap generator will copy it verbatim.
- **Locale roots emit as FLAT files** (`dist/sl.html`), not nested (`dist/sl/index.html`): hosts 301 a directory URL to its trailing-slash form, so nested output makes the canonical and hreflang (`/sl`, no slash) point at a redirect.
- **The registry pattern**: keep exceptional routes (single-locale, special chrome) in one small JSON registry read by ALL consumers — router, head composable, build assertion. Mismatch between any two fails the build, which makes the correctness bidirectional: wrong head call fails, missing route fails, unregistered page fails.
- JSON-LD: emit in setup (not on mount) so it prerenders; unique `id` per script node or the head library dedupes one node into another (e.g. a page's Service node replacing the site-wide org node). Derive every node FROM the content objects so markup can't drift from visible copy. Org node gets a stable `@id`; per-page nodes reference it as `provider`/`publisher`. Breadcrumb JSON-LD mirrors a *visible* breadcrumb trail. Offers carry `priceSpecification` with VAT flag and a description naming excluded fees — a bare price misrepresents.
- **Check Google's CURRENT supported-markup list before targeting any rich result** — the set is shrinking, not growing (FAQ restricted to government/health in May 2026; HowTo and seven other types dropped through 2025). Emit JSON-LD for entity understanding — knowledge panel, AI answer engines — not for a rich-result feature that may no longer exist. Deprecated markup isn't penalized, just ignored, so there's no cost to leaving it; there IS a cost to designing a page around a feature that's gone.
- **An explicit `<meta name="robots" content="index, follow">` is a no-op** — it is every crawler's default, and Google documents it as unnecessary. Add it only for auditors who grep for the tag, and then from ONE shared constant emitted by EVERY head builder: in project 1 the shared head wrappers covered 31 of 104 pages, because the blog built its own head and silently skipped them. A `noindex` page must never get it — make found → index / missing → noindex a single ternary. Verify the partition on the build: index + noindex = total pages, "both" = 0, "neither" = 0.
- URLs live in ONE constants module (+ the registry). Then a URL rename is a two-file edit and canonicals, hreflang, breadcrumbs and sitemap follow automatically; add the 301s and done.
- Rotators/tickers: the server-rendered first item and the runtime's first tick must name the SAME item — one shared ordering function feeds both the prerender markup and the client, never a sort duplicated in two places (or the first tick visibly swaps the text).

## First-paint veil (optional intro)

- The veil lives INLINE in the HTML shell: static HTML + CSS only — no JS dependency to appear, no webfont references (a swap mid-intro is visible), no images. It paints before anything else and hides the staged SPA load (chrome → lazy chunk → font swap → hero decode).
- The lift runs in JS but every wait is TIME-CAPPED (router ready; `fonts.ready` capped ~3.5s; hero `decode()` capped ~2s; plus a minimum showing so the intro reads intentional). The veil must be unable to hang the page.
- Two escapes exist WITHOUT JS: a `<noscript>` block that drops the veil outright, and a pure-CSS failsafe animation (~9s) that reveals the page if the app never boots.
- The veiled user can't scroll, so any non-zero scroll position at lift is a stray restore (browser or router) — reveal at the top unless a hash deep-link owns the position.

## Touch & gesture (iOS WebKit)

Everything below was paid for on real iPhones. All iOS browsers are WebKit — Chrome/Brave on iOS included — so "Safari vs Brave on the same phone" isolates the Safari app layer, not the engine.

- **`Touch.identifier` is a `long` with no sign guarantee.** Blink counts up from 0; iOS WebKit derives it per web process and hands out large values of EITHER sign (measured: −1458752544). Never a sentinel comparison (`id < 0` = "no gesture") — track gesture liveness in its own boolean and compare the identifier only with `===` against the touch list. The sign holds for the process's life and flips on a recycle, so the failure signature is a touch feature that "breaks by itself and fixes itself with no code change", per device, surviving reloads.
- **Pannable scenes render to canvas, not SVG.** iOS's shipping SVG engine cannot composite inner SVG elements: panning either repaints the whole SVG per frame (chop) or lazily rasterizes tiles (background-colored squares chasing the finger). One canvas redraws the complete scene synchronously per frame; the draw loop idles when nothing animates.
- **Drive the pan from a DOCUMENT-level non-passive `touchmove`, not from the element.** The moment WebKit claims a touch as a scroll it stops delivering moves to the ELEMENT and fires touchcancel — no `touch-action` rescues a handler the events no longer reach. The document listener sees every move; its `preventDefault` on the FIRST move is what stops the claim; and one handler both holds the scroll lock and moves the scene, so the two can never disagree about who owns the gesture.
- **The collapsed/in-page state carries ZERO touch listeners.** Merely registering a non-passive `touchmove` marks the region non-fast-scrollable, pulling page scroll off the compositor — and iOS then does NOT hand un-prevented gestures back to native scrolling (desktop Chrome does, which is why it only breaks on iPhones). Wire listeners at overlay entry, unwire at exit; the inert preview gets `touch-action: pan-y` and click handlers only.
- **Scroll lock, in this order:** capture `scrollY` FIRST (the lock completes an in-flight scroll by jumping it to its landing position — 47px measured), then `overflow: hidden` on html+body (the only reliable iOS momentum kill — a programmatic scrollTo does not stop coasting, and a page still coasting when the next touch lands makes iOS claim that touch as stop-the-scroll, every move arriving `cancelable: false`), then snap back to the captured offset in the same frame. A passive scroll listener re-pins the offset against fling-tail leaks. Never `position: fixed` on body — iOS mis-positions fixed DESCENDANTS of a fixed body.
- **Temporal input state is a bounded timestamp, never a flag** (`frozenUntil = now + MS`; checked as `now < frozenUntil`). A stale timestamp lies in the past, which reads as "not frozen"; a wedged boolean is input dead forever — invisible until someone drags.
- **Settle window for auto-opened surfaces:** arm it at ENTRY, when the pan handlers go live — not at landing; the stray movement it absorbs happens DURING the entry animation. Frozen moves still `preventDefault` (the scroll lock depends on it) and taps still pass. Re-base the pan reference every frozen frame so expiry doesn't leap by the absorbed distance, and re-base velocity with it so lift-off doesn't fling. A deliberate (tap) entry clears the window outright — a leftover timestamp from a recently closed auto-entry would freeze it.
- **Suppress the synthesized click after a drag** (flag set on gesture-end-with-movement, consumed by ONE capture-phase click listener) or every pan opens whatever it ended over. Judge "was this a drag" against the gesture ORIGIN, never against a re-based pan reference.
- **Dodge the left ~24px at touchstart** — that's the iOS edge back-swipe zone.
- **The status-bar strip is painted from the PAGE, not the meta.** With `viewport-fit=cover`, iOS Safari tints the strip behind the status bar (and the overscroll) by SAMPLING the painted html/body background; the `theme-color` meta and the manifest's `theme_color` are ignored for it. Set BOTH html and body to the chrome color; the app root paints the content surface on top, so body's color is dead paint that only iOS reads. The tell that you're in this trap: meta correct, topmost element at y=0 correct, strip still wrong — while a `position:fixed` overlay DOES change it (that's the sampler following the paint).

## Effects lifecycle (SPA that hydrates)

- Route ALL rAF loops, timers, observers, listeners, and Web Animations through a tracker (`fx.raf/setTimeout/IO/on/anim`) whose `dispose()` runs on unmount — otherwise effects stack per navigation. (confirmed in 2nd project; its tracker also drops finished animations from the set so a long session doesn't grow it unbounded)
- **WAAPI traps (each verified the hard way):**
  - `endDelay` is inert with `iterations: Infinity` — active duration is Infinity, the delay never arrives, the loop repeats back-to-back. The pause must live INSIDE the keyframes: one iteration spans sweep + hold-at-zero-opacity tail.
  - `fill: 'forwards'` is NOT a resting state. It holds only while the animation object exists — and an animation that never advanced (non-compositing renderer, throttled tab) is still applying its FIRST keyframe, so clearing inline styles isn't enough either. A `settle()` helper runs once on finish/cancel/timeout: restore the resting state to the stylesheet, then **cancel the animation**.
  - Best of all: design animations whose last keyframe equals the stylesheet's resting value and use `fill: 'none'` — no end state to defend, cancel-safe at any instant, no settle needed.
  - State every property in every keyframe — per-property interval lists have engine-ambiguous easing.
- **IntersectionObserver discipline:** observe the host, never a 1px/zero-area ornament; `unobserve` on first fire for one-shots; safety-net timeout disconnects FIRST then force-shows (else the next scroll re-fires on visible content and blinks it); bail out entirely when IO is absent rather than hiding content you can't un-hide.
- **Injected ornament contract:** aria-hidden, text-free, pointer-events:none, born hidden via JS cssText, re-entrancy-guarded (`:scope > [data-x]` check), z-indexed above the host's content wrappers, and dies with the subtree.
- **Canvas backdrops:** size can measure 0 at mount (fonts/layout) — bounded re-measure retries; paint one frame synchronously before entering the rAF loop (a throttled renderer may never fire it); gate the loop on visibility so it pauses off-screen; a fade-in is a one-shot flag because the start function re-runs on every viewport re-entry.
- Loops the visitor should see on scroll: start paused, `play()` on intersect, `pause()` on leave.
- Collapsing content ABOVE (or at) the control the user just tapped dumps them somewhere unrelated — the page slides up under a scroll offset that didn't change. Hold the tapped control still: each frame of the collapse transition, measure its drift and take exactly that out of the scroll position (`behavior:'instant'` — see trap 10), for the transition duration plus a beat. Under reduced motion the first frame corrects everything and the rest find nothing to do.
- Skip text sweeps and blanking animations when `document.hidden` — rAF is suspended there and the page would sit blanked mid-sweep until the tab returns.
- Gate hover-state WIRING on `matchMedia('(hover: hover)')` — on touch, `mouseleave` never fires and applied hover styles stick. Keep focus states everywhere (keyboard works on every device).
- Third-party widget loaders (captcha etc.): one script-load promise for the document's lifetime — the view remounts per navigation/locale switch and would stack copies. Resolve `null` on load failure and DEGRADE OPEN: a captcha that failed to arrive must not lock real people out of the only contact route.

## Forms on a static site (no backend)

- Client-side `fetch` POST to a form API, wired in mount. A real `<form>` with `type="submit"` — a div-with-button pattern makes `required`/`type="email"` inert. Boolean attributes: PRESENCE is true (`novalidate="false"` disables validation).
- Captcha client-side only, never in prerendered HTML. Render explicitly (auto-render misses SPA-mounted forms), send the token in the JSON body, and degrade open: if the widget failed to load, submit without it rather than trapping a visitor. Selects get an empty placeholder option so the form can't fabricate an answer.
- Honeypot + client validation (required fields, email shape) BEFORE posting; disable the button and swap its label while sending; color-coded status line; clear on success. Status strings live in the content module (localized), never hardcoded in the helper.
- **Degrade-open is the default, not a law — the owner may choose STRICT** (captcha mandatory: declined consent or a blocked script blocks the submit). Project 1 shipped strict on the owner's instruction. Name both costs before building it: every blocked-submit message must name the alternative contact route (e-mail/phone) — that route, not a fallback, is then what satisfies WCAG 3.3.8 — and a visitor whose extension blocks the vendor script cannot submit at all. Gate order in the submit handler: no consent → neutral message + reopen the consent notice; consent but no widget → "didn't load" message, never post; widget unsolved → the solve prompt.
- Optional hardening that never gates a human: stamp the form's render time and reject sub-2-second submissions alongside the honeypot. Both filter bots without asking a person to prove anything — which is also why the degrade-open captcha rule satisfies WCAG 3.3.8.

## Analytics & consent (third-party scripts)

- **GA4 (gtag.js) in a prerendered SPA:** put the snippet in the HTML shell's `<head>` (it lands in every prerendered page and loads before hydration), configured with `send_page_view: false`, and send every page view from the router's `afterEach` — the first one included; afterEach DOES fire for the initial navigation (verified: exactly one on a hard load). Pasted verbatim, gtag's automatic once-per-load page view records ONE view per visit however many pages were read, and every session reads as a bounce.
- **Read `document.title` a frame late.** afterEach fires when the navigation is confirmed, but the head library patches the title asynchronously — a synchronous read reports the PREVIOUS page's title. Wait one rAF, with a ~120ms timeout fallback (rAF doesn't fire in background tabs).
- Keep every vendor call in ONE module (`lib/analytics.ts`) — that is also the only place a consent gate ever needs to go (for GA in the EEA: Google Consent Mode).
- Verify transmission, not just execution: `window.dataLayer` shows what was queued; to prove hits LEAVE the browser, hook `fetch`/`sendBeacon`/`Image` and look for `google-analytics.com/g/collect?…&tid=<id>`. A network panel opened after load misses the early ones.
- The analytics stream URL should match the canonical origin (www vs apex). Collection keys on the measurement ID so data flows anyway, but reports and referral rules should describe the real site.
- **Cookie consent**, once an audit finds a non-essential cookie source: the banner renders NOTHING into the prerendered HTML (`v-if` false until `onMounted` reads the stored choice — no hydration mismatch, no CLS); the vendor script loads only after consent; Allow and Decline are identically styled (equal prominence is the legal requirement); a "cookie settings" control in EVERY footer variant reopens it (withdrawal as easy as consent); store the choice versioned (`v1:accepted`) so a policy change can re-prompt, behind try/catch (private modes throw on storage). Full recipe: the `cookie-consent` skill.

## Assets

- Self-host fonts, subset, `font-display: swap`. (confirmed in 2nd project: per-script unicode-range subsets)
- **Pair `swap` with a metric-matched fallback or the swap reflows the page.** Define a fallback `@font-face` per family over a local base (Arial/Georgia) with `size-adjust`, `ascent-override`, `descent-override` tuned to the webfont — generate them (fontaine, capsize), never hand-tune. Then the swap changes glyphs, not geometry: near-zero CLS on every hard load, not just the veiled first one. `<link rel="preload">` the 1–2 subset files used above the fold.
- Images: explicit width/height (CLS), `loading="lazy" decoding="async"` below the fold. Text is never an image: crop a supplied logo to its emblem and set the wordmark in real type — it lands in the prerendered HTML and survives any surface color.
- **The LCP element is never lazy-loaded.** Load the hero image eagerly with `fetchpriority="high"`, and `<link rel="preload">` it from the head when it's an `<img>` (skip preload for inline SVG/canvas). Lazy-loading the LCP image is the most common self-inflicted LCP regression there is — and the blanket "lazy below the fold" rule is exactly how it happens.
- **Responsive images are a build-time rule, not a CDN option.** Every content image ships `srcset` width variants with a `sizes` attribute matching the real layout, AVIF first with WebP/JPEG fallback (`<picture>` or content negotiation). Generate the variants at build on an SSG — no runtime CDN dependency. A 1600px JPEG served to a 390px phone is a self-inflicted LCP tax.
- An image with an opaque baked-in background either sits on a matching surface or gets cropped to its solid region — never plated on a contrasting fill.
- Anchor targets need `scroll-margin-top` under a fixed header — same-page `#` links are native scrolls that never see the router's offset; the offset grows where the header wraps to two rows on mobile.
- Hash navigations measure their offset only after the target exists AND fonts have loaded — poll with `setTimeout`, not rAF (background tabs throttle rAF), bounded tries, then scroll anyway.
- Share/OG images and raster favicons come from a committed one-off script (SVG composed with the brand's real fonts → PNG/JPG), outputs committed to `public/` — not part of the host build. SVG rasterizers (resvg) read TTF/OTF only: decompress the site's woff2 first. SVG is XML — escape `&` in text.
- Keep page-specific styles scoped (not global) when a critical-CSS inliner is on, or every page's head carries every page's CSS.
- Dynamic-import globs have shape constraints (e.g. `./views/*.vue` doesn't cross a `/`) — know them before nesting view files.

## Build guards — the pipeline is the CI

- After prerender, run assertion scripts that exit non-zero on: wrong `<html lang>` vs the emitted file's path, non-self-consistent canonical, missing/wrong hreflang alternates (parse the link tags, don't substring-match), empty title. **If a guard fails, fix the page — never weaken the assertion.**
- **Assert the social tags too**: `og:title`, `og:description`, `og:image` (1200×630), `og:url` equal to the canonical, `og:locale` (+ alternates on multilingual pages), `twitter:card = summary_large_image`. These are generated like canonicals and break as silently; a share that renders as a bare URL is a conversion leak nobody reports.
- **Assert exactly one non-empty `<h1>` per page, present in the static HTML.** Implied by the litmus test, so make it explicit — zero or three h1s is the kind of thing that survives every visual review.
- Generate the sitemap FROM the emitted HTML (canonical → `<loc>`, hreflang → alternates; skip 404 and noindex pages) so it cannot drift by construction.
- Wire guards into the build command so a failure blocks the deploy.

## Verify like a crawler

- The dev server always looks fine (it runs JS). Verify the BUILT output: `curl` routes and grep for h1s, canonicals, article bodies. Best: fetch production with an AI-crawler UA and confirm content with no JS.
- Grep gotchas: prerendered HTML is one minified line — `grep -c` counts lines (always 1); use `grep -oE 'pat' | wc -l`. An SVG `<title>` is not the document title.
- Assert every copy string from the content modules is greppable in the emitted HTML (script it: extract long string literals, HTML-escape, check).
- After animation work: force-finish all finite animations, then assert nothing readable is below opacity 1 and no inline styles are stranded; navigate back and forth repeatedly and assert injected nodes don't accumulate; force hover geometry and animated extremes, then re-check overflow at 320–375px.
- Headless/preview renderers may not composite: animations sit frozen at frame 0, IO never fires callbacks, screenshots fail. That produces FALSE bug reports — verify by shimming IO and driving callbacks by hand, `finish()`ing animations, and reading target values, and say plainly when you've measured rather than seen. Patch instrumentation (e.g. wrapping `Element.prototype.animate`) once, guarded, or your own hook double-counts. (confirmed in 2nd project)
- Background/hidden panes also throttle timers to ~1fps and suspend rAF — wall-clock tests there are pure noise. Take the clock instead: override `performance.now` and rAF with a virtual clock plus a manual frame pump, and run the WHOLE test sequence in one evaluation (real timers between separate calls desync the virtual clock).
- Reproduce WebKit's touch behavior synthetically: dispatch `TouchEvent`s carrying a NEGATIVE `Touch.identifier`, pump a frame per move, and record `e.defaultPrevented` per move — one run proves the pan AND the scroll lock.
- Observe internal state without instrumenting app code: a guarded prototype probe (e.g. wrap `CanvasRenderingContext2D.setTransform`) reads what the draw loop actually applies.
- When the failing platform has no reachable inspector (iOS Safari from a Windows dev box): ship a URL-flag-gated on-screen forensics HUD — capture-phase event tallies (what the browser DELIVERS) beside the handlers' own bail-reason counters (WHY a delivered event did nothing), `pointer-events: none`, zero cost and zero DOM without the flag. One screenshot from the device names the mechanism. Remove it once it has answered; keep the commit for cherry-pick.
- Before any code archaeology on "works here, broken there": verify WHICH bytes the failing device runs — marker-grep the served bundles (see deployment.md). Months-old deploys on stale URLs explain more "impossible" bugs than code does.
- **Guards prove correctness, never speed.** Check Core Web Vitals FIELD data (Search Console / CrUX) per template about monthly after launch. Thresholds: LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1 at p75. Lab runs are a debugging tool only — field data is the truth and lags ~28 days, so never declare a performance fix done from a Lighthouse score.

## Optional enhancements (progressive only)

Platform features that shipped after the stack choices above. Every one is additive and feature-detected: the page must be complete and correct without it, so none of them is ever load-bearing. Adopt per project, not by default.

- **Same-document View Transitions** (Baseline since Oct 2025): wrap SPA route changes in `document.startViewTransition` where supported, gated on `prefers-reduced-motion`. Keep it to subtle continuity or it stops being instrumentation and becomes decoration. (Cross-document VT lacks Firefox — irrelevant while in-site nav is SPA.)
- **Speculation Rules** (Chromium only, not Baseline): one feature-detected `<script type="speculationrules">` prefetch block for entry pages, at most. Modest win when a click interceptor already gives SPA navigation.
- **Scroll-driven animations** (`animation-timeline`): Chromium and Safari ship it, Firefox still behind a flag. **IntersectionObserver stays the baseline** — it's the only cross-browser mechanism; revisit when Firefox ships.
- **`content-visibility: auto`** with `contain-intrinsic-size` on long below-the-fold sections (Baseline since late 2024): cheap rendering-cost win on multi-section pages.

## Litmus test

Open the page with JavaScript disabled. If the headings, copy, links, title, canonical, and hreflang aren't all there, a crawler can't see them — and neither can an AI answer engine.
